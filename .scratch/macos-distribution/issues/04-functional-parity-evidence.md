# 定义功能一致性的独立认证协议

Type: grilling
Status: resolved

## Question

如何用净室式独立验证证明 macOS 薄壳没有改变现有 Windows 功能，并留下可复核的
可靠性证据？

至少需要确定：

- 以什么 Windows 行为作为黑盒基准：界面截图、交互流程、文件副作用还是接口响应。
- 认证者与实现者如何隔离，认证结果如何保存到仓库。
- 使用模型覆盖哪些真实流程，例如打开笔记库、编辑保存、搜索、附件、Git 提交。
- “成功率不低于 99.9%”和“不得损坏笔记或 Git 数据”如何采样、计算和复现。
- 哪些失败必须阻断发布，哪些只记录为平台差异。

## Answer

接受以下独立认证门槛：

- 实现者与认证者是不同代理或不同人员。
- 使用真实工作流建立加权使用模型，覆盖打开笔记库、编辑保存、搜索、附件、
  Git 暂存提交等主要路径。
- macOS 特定桥接与薄壳按使用模型抽样 3,000 次，零失败且零笔记或 Git 数据损坏。
- 至少 50 条独立端到端界面流程全部通过。
- 保存环境、固定种子、输入夹具、命令、日志、截图和结果清单；实现者不能自行
  签署 `CERTIFIED`。
